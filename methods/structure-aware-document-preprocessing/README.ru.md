**Проблема:** Стандартный подход к разбивке документов на чанки (нарезка по числу токенов) разрушает семантическую структуру: таблица может быть разрезана посередине, пронумерованный список разбит на несвязанные фрагменты, заголовок оторван от относящегося к нему текста. Агент, получивший фрагмент таблицы без заголовка или строку списка без контекста, не способен корректно интерпретировать данные.

**Решение:** Перед разбивкой на чанки документ обрабатывается структурно-осознанным парсером (например, Docling или аналогичным VLM-инструментом). Парсер выдаёт размеченный промежуточный формат, в котором явно указаны границы таблиц, заголовков, списков, подписей к рисункам, формул. Разбивка на чанки происходит только по этим семантическим границам — таблица всегда остаётся единым чанком, список не разрывается между чанками. Для документов со сложной структурой (финансовые отчёты, технические спецификации) применяется дополнительный VLM-этап распознавания визуальных элементов.

**Пример:** PDF-документ содержит таблицу с 12 строками. При «слепом» разбиении по токенам таблица разрезается после 7-й строки: первый чанк получает строки 1–7 с заголовком, второй — строки 8–12 без заголовка. Агент, получив второй чанк, не может определить, к каким столбцам относятся данные. При структурно-осознанном препроцессинге таблица остаётся единым чанком, агент получает её целиком и даёт корректный ответ.

**Экспериментальная проверка:** Создать PDF с таблицей размером, превышающим стандартный лимит токенов для одного чанка. Запросить данные из второй половины таблицы в двух режимах: слепое разбиение и структурно-осознанный препроцессинг. В первом режиме агент не должен дать корректный ответ. Во втором — должен.
