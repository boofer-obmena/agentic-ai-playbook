**Проблема:** Без жёстких ограничений на формат вывода LLM генерирует свободный нарратив, трудно поддающийся автоматической обработке. При отсутствии данных модель склонна галлюцинировать — заполнять пробелы правдоподобными, но выдуманными утверждениями. В агентном конвейере оба явления приводят к ошибкам.

**Решение:** Каждый агент работает с жёстким выходным шаблоном, реализованным через комбинацию трёх механизмов. JSON-схема (структурный контракт): определяет обязательные поля, их типы и допустимые значения. Few-Shot примеры: несколько образцов корректного вывода, демонстрирующих ожидаемый стиль и уровень детализации. Chain-of-Thought с доказательствами: для каждого утверждения агент обязан указать поле evidence — прямую цитату или ссылку на конкретный фрагмент входных данных, из которого сделан вывод. При отсутствии данных агент обязан явно указать «Данные отсутствуют» вместо генерации предположений.

**Пример:** Агент-аналитик формирует ФТ на основе User Story. Для каждого пункта ФТ в поле evidence указывается точная цитата из User Story: «Основание: Пользователь должен иметь возможность отменить заказ в течение 24 часов после оформления (User Story US-047, пункт 3)». Аудитор проверяет: для каждого пункта ФТ цитата из evidence реально присутствует в исходном документе User Story.

**Экспериментальная проверка:** Дать агенту задачу, где часть необходимых данных намеренно отсутствует (неполная User Story). Проверить: агент не галлюцинирует — он явно помечает пункты, для которых данные отсутствуют, как «Требует уточнения». Для присутствующих данных все поля evidence заполнены корректными ссылками.

**История применения:** Не применялся. Раздел заполняется по результатам реального использования паттерна: контекст задачи, что сработало, что потребовало корректировки, итоговые выводы.
