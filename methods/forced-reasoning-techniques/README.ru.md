**Проблема:** LLM по умолчанию генерирует ответ за один прямой проход — от вопроса к ответу без промежуточных шагов. На сложных задачах (математика, многошаговое планирование, логический анализ, юридические рассуждения) такой «интуитивный прыжок» даёт высокую вероятность ошибки. Модель «угадывает» ответ вместо того, чтобы вычислять его. При этом архитектурные паттерны (Reflection, Дебаты, Планирование) нуждаются в инструментах усиления рассуждения на уровне отдельного LLM-вызова — но сами по себе не решают проблему «как заставить модель думать, а не угадывать».

**Решение:** Семейство промпт-техник, заставляющих модель явно выстраивать цепочку рассуждений перед финальным ответом. Техники отличаются по вычислительной стоимости, глубине исследования и надёжности — разработчик выбирает технику под класс задачи.

---

**Chain-of-Thought (CoT) — линейное рассуждение.** Модель получает промпт, к которому добавлена инструкция выводить промежуточные шаги: «Давайте подумаем пошагово». Вместо прямого ответа модель последовательно проговаривает: «Дано: … Из этого следует: … Вычислим: … Проверим граничные условия: … Ответ: X». Каждый шаг опирается на предыдущий, логическая ошибка становится видимой (и потенциально исправимой моделью) до достижения финального ответа.

CoT — базовая техника, один вызов модели. Современные модели (Claude, GPT-4) поддерживают встроенный thinking-режим, при котором цепочка рассуждений генерируется внутри модели и не показывается пользователю. CoT повышает точность ценой роста latency ~2x и расхода токенов на скрытую цепочку.

**Tree-of-Thoughts (ToT) — ветвящееся исследовательское рассуждение.** Модель не идёт по одной цепочке, а на каждом шагу генерирует несколько вариантов продолжения (обычно 3–5), оценивает каждый по заданному критерию и развивает лучший. Если ветка заходит в тупик — возвращается к предыдущей развилке и пробует альтернативу. Аналогия: шахматный движок, перебирающий варианты ходов с оценкой позиции.

ToT требует нескольких последовательных вызовов модели: генератор → оценщик → выбор → продолжение. Это значительно дороже CoT по latency и токенам, но даёт выигрыш на задачах с большим пространством решений и неочевидным путём к ответу: творческое письмо, стратегическое планирование, поиск нестандартных архитектурных альтернатив.

**Self-Consistency — статистическая стабилизация.** Один и тот же CoT-промпт запускается N раз (обычно 5–7), и выбирается ответ, встретившийся чаще всего (majority voting). LLM вероятностна: при разных запусках один и тот же промпт даёт немного разные ответы. Self-Consistency превращает этот недостаток в преимущество — случайные ошибки и галлюцинации отсеиваются голосованием, консенсусный ответ статистически устойчивее любого отдельного.

Self-Consistency увеличивает стоимость в N раз, но радикально повышает точность на задачах с высокой ценой ошибки. Ортогональна к CoT и ToT — может применяться поверх любой из них.

---

**Правило выбора техники:**

| Класс задачи | Техника | Компромисс |
|---|---|---|
| Рутинный фактологический запрос | Без техник | Минимальная стоимость |
| Логика, математика, дедукция | CoT | +latency ~2x |
| Открытое исследование, стратегия, креатив | ToT | +latency ~5–10x |
| Высокая цена ошибки (юриспруденция, медицина, финансы) | CoT + Self-Consistency | +стоимость ~5x |

**Пример:** Агент-аналитик в составе PATTERN-021 (Дебаты) получает задачу: «Какой стек выбрать для высоконагруженного real-time пайплайна при ограниченном бюджете?» Вместо прямого CoT-рассуждения запускается ToT: модель генерирует 3 альтернативы архитектуры стека, для каждой оценивает latency, стоимость и риск, отсекает заведомо нерабочую ветку, углубляет две оставшиеся, сравнивает их и выдаёт финальную рекомендацию с обоснованием. Результат передаётся в Дебаты, где другие роли оспаривают отдельные аспекты выбора.

**Связь с другими сущностями:** Используется паттернами: PATTERN-043 (Reflection) — CoT на шаге «Критика»; PATTERN-021 (Дебаты) — CoT или ToT на шаге аргументации роли; PATTERN-006 (Планирование) — CoT на шаге генерации плана; PATTERN-017 (Динамическая онтология) — ToT для исследования семантических связей. Связан с PRINCIPLE-011 (Think mode) — think: true в терминах Claude API есть реализация CoT на уровне модели.

**Экспериментальная проверка:** Требуется. План: выбрать 3 класса задач (логическая, творческая, high-stakes), для каждого прогнать 3 режима (прямой ответ / CoT / ToT+Self-Consistency), измерить точность и стоимость. Сравнить CoT со встроенным thinking-режимом Claude.

**История применения:** Не применялся. Статус: raw.
