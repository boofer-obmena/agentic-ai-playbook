**Проблема:** При длительных многоэтапных задачах агент накапливает значительный контекст: промежуточные результаты, принятые решения, обнаруженные зависимости. При сбое (таймаут, ошибка инструмента, переполнение контекстного окна) весь этот контекст теряется, и задачу приходится начинать с нуля. Для сложных задач это означает повторное расходование часов работы и значительного бюджета токенов.

**Решение:** В критических точках задачи (после завершения каждого крупного этапа) сохраняется Контрольная точка — компактное векторное представление текущего состояния агента: выполненные шаги, принятые решения, промежуточные результаты, текущий план. При возобновлении после сбоя агент не перечитывает всю историю — он загружает последнюю Контрольную точку и получает компактный контекст + дифф (что изменилось с момента сохранения). Контрольные точки хранятся в специализированном хранилище, отдельном от основной базы данных задач.

**Пример:** Инженер-программист выполняет рефакторинг крупного модуля (200+ функций). После анализа первых 80 функций и построения карты зависимостей сохраняется Контрольная точка. На шаге 120 происходит таймаут. Агент возобновляет работу: загружает Контрольную точку с картой зависимостей первых 80 функций, получает дифф (функции 81–119 были обработаны до сбоя), продолжает с функции 120.

**Экспериментальная проверка:** Запустить задачу рефакторинга в 2 группах. Контрольная группа: при сбое на шаге 7 перезапускает с нуля. Экспериментальная группа: восстанавливается из последней Контрольной точки. Измерить: время восстановления, количество повторно потреблённых токенов, качество итогового результата. Ожидаемое улучшение в экспериментальной группе: снижение времени и токенов на 60%+.

**История применения:** Не применялся. Раздел заполняется по результатам реального использования паттерна: контекст задачи, что сработало, что потребовало корректировки, итоговые выводы.
