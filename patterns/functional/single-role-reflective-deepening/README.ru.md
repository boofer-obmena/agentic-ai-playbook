# Рефлексивное самоуглубление в рамках одной роли

> **Single-Role Reflective Deepening**

**Проблема:** Агент, генерирующий результат за один проход, выдаёт «первый черновик» — материал, который не прошёл внутренней проверки на полноту, глубину и соответствие изначальному запросу. Модель склонна к конфирмационному смещению: она не видит слабых мест собственной генерации, поскольку находится внутри того же контекста рассуждения, в котором этот материал был создан.

**Решение:** Агент выполняет несколько итераций работы над материалом, оставаясь в рамках одной роли. После генерации черновика агент принудительно сбрасывает контекст (deliberate disengagement) — обнуляет память генерации. Затем он возвращается к материалу «с чистого листа», используя специальный Critic-промпт, который направляет его на анализ: соответствие запросу, полнота, глубина, ширина охвата, наличие ошибок. При необходимости агент обращается к своей базе знаний за вспомогательной информацией — в том числе к материалу, напрямую с темой не связанному, способному дать неожиданный инсайт. Цикл повторяется до достижения приемлемого качества.

Ключевое архитектурное ограничение: агент не меняет роль в процессе рефлексии. Методолог остаётся методологом, инженер — инженером. Критик — это не отдельная роль, а режим работы той же роли со сброшенным контекстом и специальным промптом. Смена роли превращает Reflection в Debate (PATTERN-021).

Глубина рефлексии параметризуется через architectural knob «уровень критичности задачи»: для операционных задач с низкой ценой ошибки — однопроходная генерация без рефлексии; для задач средней критичности — две-три итерации проверки; для экспертных задач с высокой ценой ошибки — итерации до исчерпания лимита или достижения сходимости качества.

**Пример:** Проектировщик архитектуры (методолог) получает задачу описать целевую архитектуру информационной системы. Первая итерация: агент набрасывает структуру — компоненты, связи, потоки данных. Сброс контекста. Вторая итерация: агент возвращается к черновику в режиме Критика, анализирует на предмет полноты (все ли аспекты покрыты?), внутренней согласованности (нет ли противоречий?), соответствия изначальным требованиям. Обращается к базе знаний — находит описание похожей архитектуры из смежной области, видит паттерн, который не учёл. Третья итерация: дорабатывает архитектуру с учётом найденного паттерна и замечаний Критика.

**Связанные сущности:**

- Вытекает из [PHILOSOPHY-006](../PHILOSOPHY-006-primacy-of-iterative-self-deepening/): первичность итеративного самоуглубления над однопроходной генерацией
- Альтернатива [PATTERN-021](../PATTERN-021-agent-debate/): Reflection — углубление внутри одной роли; Debate — контраст между разными ролями
- Дополняет [PATTERN-014](../PATTERN-014-reflective-recovery-loop/): PATTERN-014 срабатывает реактивно при ошибке и перестраивает план; PATTERN-043 работает проактивно над качеством до выдачи результата
- Дополняет [PATTERN-020](../PATTERN-020-ratchet-loop/): PATTERN-020 оперирует на горизонте дней/недель и улучшает правила агента; PATTERN-043 работает здесь и сейчас над конкретным артефактом

**Экспериментальная проверка:** Требуется. План проверки: сравнить качество результатов агента с Reflection (2, 3, 5 итераций) против однопроходной генерации на наборе задач разной критичности. Метрики: экспертная оценка качества, время выполнения, стоимость в токенах. Определить оптимальное число итераций для каждого уровня критичности.

**История применения:** Не применялся. Статус: raw.
