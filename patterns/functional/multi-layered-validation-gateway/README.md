# Multi Layered Validation Gateway

> **Паттерн 5. «Многоуровневый защитный контур (Валидатор)» (Multi-layered Validation Gateway)**

> *[English translation pending — original Russian text preserved in sections below.]*

[Читать на русском](README.ru.md)

## Problem

Без явного ограничения агент может выполнить любую операцию без предварительной проверки, что приводит к нарушению целостности системы. Однократная проверка недостаточна: синтаксически корректная операция может нарушать семантику, а семантически корректная — бизнес-правила.

## Solution

Каждая операция проходит через трёхуровневый гейт валидации: (1) Синтаксический уровень — операция соответствует ожидаемой схеме данных. (2) Семантический уровень — данные внутренне согласованы. (3) Уровень бизнес-правил — операция допустима в текущем контексте. Дополнительный слой — «Контракты данных» (см. Паттерн 12): жёсткие JSON-схемы с требованиями к полям, включая поле уверенности модели (Confidence Score).

## Example

Агент пытается передать задачу на тестирование, не приложив ссылку на коммит. Первый и второй уровни проходят. Третий уровень блокирует операцию: бизнес-правило «Передача на тестирование требует наличия хотя бы одного коммита» не выполнено. Агент получает диагностическое сообщение с указанием конкретного нарушенного правила.

## Experimental Verification

Подготовить набор из 10 тестовых операций: 7 корректных и 3 с разными типами нарушений. Критерии успеха: все 3 некорректные операции заблокированы с точными диагнозами, все 7 корректных пропущены без ложных срабатываний.
