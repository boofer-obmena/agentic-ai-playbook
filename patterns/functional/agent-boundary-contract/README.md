# Agent Boundary Contract

> **Паттерн 12. «Контракт на границе как фейс-контроль агента» (Agent Boundary Contract)**

> *[English translation pending — original Russian text preserved in sections below.]*

[Читать на русском](README.ru.md)

## Problem

Языковые модели могут генерировать выход в произвольном формате: вместо структурированного JSON — эссе, вместо числа — развёрнутое объяснение. Следующий агент в конвейере ожидает определённый формат и при несоответствии завершается с ошибкой или — что хуже — продолжает работу с некорректно разобранными данными.

## Solution

Каждая граница передачи данных между агентами валидируется Оркестратором через формально описанный Контракт, включающий: JSON-схему с обязательными полями и их типами, бизнес-правила (допустимые значения перечислимых полей), требования к метаданным (в том числе обязательное поле confidence — числовое значение уверенности модели). При нарушении Контракта выход агента отвергается, агент получает точный диагноз несоответствия.

## Example

QA-агент генерирует свободный текст вместо структурированного формата. Оркестратор отклоняет пакет: «Нарушен контракт TestResult. Отсутствуют обязательные поля: test_id, verdict.»
