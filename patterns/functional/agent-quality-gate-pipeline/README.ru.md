# Контроль качества в жизненном цикле агента

> **Agent Quality Gate Pipeline**

**Проблема:** Оценка качества работы агента обычно сводится к двум мерам: субъективная оценка человека («выглядит хорошо / не выглядит») и итоговая точность результата, если её можно измерить объективно. Этого недостаточно для промышленных агентных систем. Человек не может оценивать каждый выход каждого агента — это не масштабируется. Субъективная оценка неконсистентна — один и тот же человек оценивает один и тот же результат по-разному в зависимости от времени суток и усталости. А отсутствие промежуточных ворот качества означает, что деградация агента обнаруживается только после того, как результат уже доставлен — post-mortem, а не проактивно.

**Решение:** В архитектуру агентной системы вводится внешний контур оценки качества — конвейер автоматизированных ворот качества (quality gates), которые действуют независимо от оцениваемого агента и дают количественный, воспроизводимый сигнал качества на нескольких этапах жизненного цикла агента.

Golden Set Regression. Поддерживается курируемый набор пар «вход — ожидаемый выход» — задач, для которых правильный ответ известен с высокой уверенностью. После каждого обновления агента (смена модели, смена промпта, смена правил через PATTERN-020) агент прогоняется через Golden Set. Фиксируется регрессия, если точность агента на Golden Set упала ниже порога. Это smoke test: не «насколько агент хорош?», а «стал ли агент хуже своей предыдущей версии?»

LLM-as-Judge. Для задач, где правильный ответ нельзя определить алгоритмически, отдельный агент-Судья (Judge) оценивает результат исполняющего агента по рубрике (rubric). Судья — не тот же агент с другим промптом, а архитектурно отдельный компонент со своей рубрикой оценки, своим контекстом и без доступа к контексту генерации исполняющего агента. Судья возвращает структурированный вердикт: (a) общая оценка качества (0–1), (b) покритериальная разбивка (полнота, точность, релевантность, непротиворечивость), (c) конкретные проблемы со ссылками на артефакт. Рубрика Судьи — основной конфигурационный артефакт ворот качества: она определяет, что значит «хорошо» для каждого типа агента.

Размещение ворот качества. Ворота качества позиционируются в трёх точках жизненного цикла агента: (1) Предотправочные ворота (pre-delivery gate) — результат агента проходит через Судью до попадания к человеку; при оценке ниже порога результат уходит на внутреннюю доработку (PATTERN-043), а не к человеку. (2) Постобновленческие ворота (post-update gate) — Golden Set Regression после каждого обновления агента; падение ниже порога блокирует попадание обновления в production. (3) Периодический аудит (periodic audit gate) — плановый полный прогон агента через расширенный оценочный набор; выявляет медленную деградацию (model drift), которую единичные предотправочные ворота могут пропустить.

Ворота качества — не гарантия качества. Это автоматизированный сигнал для человеческого внимания. Предотправочные ворота не заменяют человека — они отфильтровывают результаты, однозначно не дотягивающие до планки качества, чтобы человек просматривал только результаты с неоднозначным или высоким сигналом качества.

Обратная связь качества. Вердикты Судьи накапливаются со временем. Храповой цикл (PATTERN-020) использует их для выявления системных слабостей: если Судья постоянно отмечает «неполноту» для данного типа агента — это становится кандидатом на изменение правил или уточнение промпта. Активное обучение (PATTERN-030) использует отбракованные Судьёй результаты как кандидаты на человеческую коррекцию — худшие по оценке результаты являются наиболее высокосигнальными обучающими примерами.

**Пример:** Агент-аналитик генерирует договор. Прежде чем договор попадёт к клиенту, срабатывают предотправочные ворота: агент-Судья оценивает договор по рубрике — полнота (все ли требуемые пункты присутствуют?), точность (корректны ли юридические отсылки?), непротиворечивость (нет ли противоречащих друг другу пунктов?). Судья возвращает оценку 0.72 — ниже предотправочного порога 0.85. Ворота качества направляют договор обратно агенту с конкретными замечаниями Судьи: «пункт 4.2 противоречит пункту 3.1 в части языка ответственности; отсутствует раздел форс-мажор». Агент выполняет внутреннюю рефлексию (PATTERN-043) и дорабатывает договор. Второй проход: 0.91 — доставлен человеку. Человек видит уже проверенный договор, просматривает только отмеченные секции и утверждает.

Через неделю агент обновлён с новым промптом. Постобновленческие ворота запускают Golden Set Regression: точность упала с 0.88 до 0.81 — регрессия зафиксирована. Обновление заблокировано. Команда исследует: новый промпт непреднамеренно изменил поведение агента на специфическом типе договоров. Промпт исправлен, Golden Set пройден — обновление допущено.

**Связанные сущности:**

- [PATTERN-002](../PATTERN-002-agent-auditor/): Судья — специализированный экземпляр Агента-Аудитора, оценивающего не архитектуру, а качество результата
- [PATTERN-043](../PATTERN-043-single-role-reflective-deepening/): запускается предотправочными воротами при оценке ниже порога — агент дорабатывает результат до попадания к человеку
- [PATTERN-044](../PATTERN-044-evolving-human-agent-trust/): ворота качества сокращают число HITL-точек, отфильтровывая результаты, однозначно не дотягивающие до планки
- [PATTERN-020](../PATTERN-020-ratchet-loop/): агрегированные вердикты Судьи поступают в Храповой цикл как сигнал для системных улучшений поведения
- [PATTERN-030](../PATTERN-030-active-learning-via-artifact-correction/): отбракованные Судьёй результаты — наиболее высокосигнальные обучающие примеры для активного обучения

**Экспериментальная проверка:** Требуется. План: развернуть агента с воротами качества и без. Замерить: (1) время ревью человека на один результат с предотправочными воротами и без, (2) частоту Golden Set регрессий, пойманных до попадания в production, (3) корреляцию между оценками Судьи и человеческими оценками качества — для калибровки рубрики.
