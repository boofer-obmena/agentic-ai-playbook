# Human Agent Trust Evolution Loop

> **Паттерн 44. «Человеко-агентный контур с эволюционирующим доверием» (Human-Agent Trust Evolution Loop)**

> *[English translation pending. Original Russian text preserved in sections below.]*

## Problem

Традиционный HITL проектируется как статический набор контрольных точек, определённых на этапе архитектуры и неизменных в процессе эксплуатации. Это игнорирует фундаментальный факт: доверие между человеком и агентом — не константа, а переменная, эволюционирующая во времени. На старте человек не доверяет агенту и хочет контролировать каждый шаг. Через месяц совместной работы контроль над частью операций становится избыточным — но система не умеет адаптировать гранулярность HITL-точек. Результат: либо дорогостоящий ручной контроль над тем, что уже можно автоматизировать, либо недостаточный контроль над тем, что ещё требует участия человека.

## Solution

В архитектуру вводится градуированная, динамически переконфигурируемая система HITL-точек, которая эволюционирует по мере роста взаимного доверия между человеком и агентом.

Три уровня гранулярности контроля. Максимальный (нулевое доверие): человек утверждает каждую операцию агента до её выполнения; агент предоставляет контекстный пакет по каждой операции. Средний (растущее доверие): часть операций автоматизирована; человек утверждает операции на ключевых развилках или операции выше порога риска; по автоматизированным операциям человек получает уведомление постфактум. Минимальный (зрелое доверие): человек утверждает только операции, требующие человеческого решения по юридическим или compliance-основаниям — независимо от технической способности агента выполнить их корректно.

Механизм эволюции. Движение между уровнями не происходит по времени — оно происходит по данным. Каждая HITL-точка, в которой человек отменяет решение агента и даёт правильный ответ, порождает обучающую пару: «решение агента → правильное решение человека». Эта пара поступает в контур активного обучения (PATTERN-030) и используется для дообучения агента. По мере роста точности агента на данном классе операций система предлагает человеку понизить уровень контроля — перевести точку из обязательного утверждения в уведомление или в автомат. Окончательное решение о снятии контроля остаётся за человеком.

Контекстный пакет. При срабатывании HITL-точки агент формирует не сырой лог, а структурированный артефакт: (1) что агент предлагает сделать, (2) почему — цепочка рассуждения, (3) альтернативные варианты, которые агент рассмотрел и отверг, с указанием причин, (4) уровень уверенности модели для данного решения, (5) потенциальные риски решения. Человек получает ровно ту информацию, которая нужна для принятия решения — без информационного шума и без потери существенных сигналов.

Точка возврата (re-entry). После получения ответа человека агент не просто продолжает с того же места. Он выполняет контекстную перезагрузку: проверяет, не изменилось ли состояние системы или внешние данные за время ожидания, интегрирует человеческое решение как новый constraint в дальнейший план и возобновляет выполнение с учётом истёкшего времени и нового ограничения.

Динамическая конфигурация. HITL-точки управляются не кодом Оркестратора, а конфигурационным файлом — например, раздел в server_rules.md согласно PATTERN-025. Изменение уровня контроля не требует пересборки системы. Человек может вручную понизить или повысить уровень в любой момент.

## Example

Заказчик впервые взаимодействует с агентом-аналитиком, который готовит договоры. Фаза 1 (нулевое доверие): заказчик настаивает на утверждении каждого пункта договора — 40 HITL-точек. Через две недели (растущее доверие): заказчик видит, что агент безошибочно готовит стандартные разделы — предмет договора, реквизиты сторон — и требует утверждения только специфических разделов — ответственность, форс-мажор, особые условия — 8 HITL-точек. Через два месяца (зрелое доверие): заказчик доверяет агенту всё, кроме цены и штрафных санкций — 2 HITL-точки, зафиксированные не технической необходимостью, а compliance-политикой компании.

## Связь с другими паттернами

HITL-точки — основной источник обучающих пар для PATTERN-030 (Активное обучение через коррекцию артефакта). Накопленные обучающие пары на горизонте дней/недель конвертируются в улучшение правил агента через PATTERN-020 (Храповой цикл). PATTERN-043 (Рефлексивное самоуглубление) работает как внутренняя проверка агента до выдачи результата; HITL подключается как внешняя проверка, когда внутренней недостаточно. Конфигурация HITL-точек живёт на Уровне 2 (оперативные правила) согласно PATTERN-025 (Трёхуровневая архитектура правил) и может изменяться без пересборки системы. Вытекает из PHILOSOPHY-007 (Доверие между человеком и агентом как эволюционирующая переменная системы).

## Experimental Verification

Требуется. План проверки: развернуть систему с тремя HITL-точками разной критичности; измерить: (1) время до первого понижения уровня контроля человеком, (2) точность агента до и после обработки обучающих пар из HITL-точек, (3) удовлетворённость человека скоростью эволюции контроля.
