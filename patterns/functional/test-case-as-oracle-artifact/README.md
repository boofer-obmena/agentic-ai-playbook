# Test Case As Oracle Artifact

> **Паттерн 7. «Тест-кейс как артефакт со встроенным оракулом» (Test Case as Oracle Artifact)**

**Проблема: Субъективная оценка результатов тестирования порождает споры и не обеспечивает воспроизводимости. Если критерий приёмки сформулирован размыто, два разных агента могут вынести противоположные вердикты для одного и того же результата.:**



**Решение: Тест-кейс является полноценным артефактом конвейера со строгой структурой: Идентификатор → Связанное требование (ссылка на ФТ) → Предусловия → Последовательность действий → Ожидаемый результат (точно сформулированный, проверяемый). Вердикт всегда бинарный: Пройден / Не пройден. Промежуточные состояния не допускаются.:**



**Пример: ФТ содержит требование: «При создании заказа с количеством товара более 1000 единиц система должна запрашивать подтверждение у менеджера». QA-агент создаёт тест-кейс: Предусловие — авторизованный пользователь с ролью «Менеджер». Действие — добавить позицию с количеством 1001 единица. Ожидаемый результат — появление диалога подтверждения с точным текстом.:**



**Экспериментальная проверка: Передать QA-агенту намеренно сломанную версию функции и корректную версию с другим текстом диалога. Проверить: обе версии получают вердикт «Не пройден» с разными, точными диагнозами.:**
