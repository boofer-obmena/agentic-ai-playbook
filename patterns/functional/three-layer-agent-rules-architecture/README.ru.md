# Паттерн 25. «Трёхуровневая архитектура правил агента» (Three-Layer Agent Rules Architecture)

**Проблема:** Системный промпт агента — статичный артефакт: его может изменить только разработчик вручную. Если туда помещается всё — роль, правила безопасности, текущая конфигурация инфраструктуры, IP-адреса, пути — промпт раздувается и устаревает. Агент работает с устаревшими данными до следующего ручного обновления.

**Решение:** Правила агента разделяются на три независимых уровня с разными правами доступа и разной частотой изменения. Уровень 1 — Фундамент (системный промпт): роль агента, категорические запреты, формат ответов, инструкция «при старте читай файл правил». Изменяется только владельцем системы вручную. Уровень 2 — Оперативные правила (файл server_rules.md): текущая конфигурация инфраструктуры, IP-адреса, пути, проверенные поведенческие правила. Агент читает файл при каждом старте через read_file. Уровень 3 — Заметки (файл server_notes.md): наблюдения, кандидаты в правила, гипотезы для улучшения. Заполняется агентом-ревьюером автономно. После верификации переносится на уровень 2.

Принцип разделения: В системный промпт — только то, что НИКОГДА не меняется. В файл правил — всё оперативное. В заметки — кандидаты, не прошедшие верификацию.

**Связь с другими паттернами:** Паттерн 20 (Ratchet Loop) — уровень 3 (заметки) является входом для цикла самоулучшения. Паттерн 10 (Инструментальный манифест) — уровень 2 может содержать актуальный манифест инструментов.

**Экспериментальная проверка:** Изменить IP-адрес в файле правил (уровень 2) без изменения системного промпта. Проверить: агент на следующей сессии использует новый IP без перезапуска. Системный промпт при этом остаётся нетронутым.

**История применения:** Применялся при создании агента-администратора сервера Mac Mini (апрель 2026). Трёхуровневая структура выработана эмпирически в ходе эксплуатации. Ключевой вывод: разделение фундамента и оперативных данных позволило обновлять конфигурацию инфраструктуры без ручного редактирования системного промпта.
