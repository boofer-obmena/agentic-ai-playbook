# Паттерн 45. «Единая модель памяти агента: четыре когнитивных уровня» (Unified Agent Memory Architecture)

[Read in English](README.md)

**Проблема:** Память агента фрагментирована по нескольким паттернам, каждый из которых решает свою часть задачи, но ни один не описывает память как целостную когнитивную систему. Разработчик вынужден самостоятельно собирать разрозненные механизмы в работающую архитектуру, не имея единой картины того, как данные движутся между уровнями памяти.

**Решение:** Память агента проектируется как четырёхуровневая когнитивная система, где каждый уровень имеет свою функцию, стратегию извлечения и механизм перехода данных на следующий уровень. Три уровня универсальны, четвёртый специфичен для высокоинтеллектуальных агентов.

**Уровень 1 — Рабочая память (Working Memory).** Текущее контекстное окно агента: разговор, выводы инструментов, промежуточные рассуждения, активные файлы. Всегда доступна, не требует поиска. Ограничена ёмкостью контекстного окна. Управляется PATTERN-027 (Семантическое сжатие контекста): при приближении к пределу токенов средняя часть контекста сжимается в резюме и передаётся на Уровень 2, освобождая место для текущей работы.

**Уровень 2 — Эпизодическая память (Episodic Memory).** Лог прошлых сессий и их исходов. Отвечает на вопрос «что случилось в прошлый раз с похожей задачей». Формируется из двух источников: сжатые резюме из рабочей памяти (PATTERN-027) и журнал сессии (PATTERN-029). Требует поиска: агент должен явно запросить релевантные эпизоды. Стратегия извлечения — поиск по семантической близости к текущей задаче.

**Уровень 3 — Семантическая память (Semantic Memory).** Факты, концепты, доменное знание, документы. Отвечает на вопрос «что система знает об этом». Живёт в векторных базах и графах знаний. Требует и поиска, и рассуждения поверх найденного. Управляется PATTERN-032 (Agentic RAG), PATTERN-033 (Семантический веер запросов) и PATTERN-037 (Мультивекторный семантический индекс).

**Уровень 4 — Процедурная память (Procedural Memory).** Правила поведения агента, извлечённые из собственного опыта. Отвечает на вопрос «как действовать в такой ситуации». В отличие от системного промпта и статических правил (PATTERN-025, Уровни 1 и 2), заданных архитектором извне, процедурная память формируется самим агентом: повторяющиеся закономерности из эпизодической памяти и обобщения из семантической со временем конденсируются в процедурные правила — «в ситуациях типа X оптимальная последовательность действий — Y». Это не просто «ещё одно хранилище», а результат работы вышележащих уровней памяти, материализованный в исполнимые инструкции.

Специфика процедурной памяти: её формирование требует достаточно высокого интеллектуального уровня агента — способности к мета-анализу собственного поведения. Для простых агентов-исполнителей она избыточна: им достаточно системного промпта и статических правил. Для аналитических агентов высокого уровня и для агентов, работающих в контуре Human-in-the-Loop (PATTERN-044), процедурная память становится значимым механизмом эволюции поведения. Включение четвёртого уровня в архитектуру — решение, принимаемое под конкретный класс агента, а не универсальное требование.

**Движение данных между уровнями.** Это ключевое архитектурное свойство unified-модели: память — не набор хранилищ, а система с направленными потоками. Рабочая → Эпизодическая: через сжатие контекста и журнал сессии. Эпизодическая → Семантическая: повторяющиеся паттерны в эпизодах обобщаются в семантические факты. Семантическая + Эпизодическая → Процедурная: закономерности из опыта и знания конденсируются в правила поведения (через Храповой цикл PATTERN-020). Семантическая + Процедурная → Рабочая: при старте задачи релевантные знания и правила загружаются в контекст.

**Связь с физическим хранением.** Когнитивные уровни не привязаны жёстко к технологии хранения. PATTERN-038 (Градиентное хранение) описывает физическое размещение данных (RAM/SSD/HDD), которое обслуживает разные когнитивные уровни. Один когнитивный уровень может использовать несколько технологий хранения — и наоборот. Разделение когнитивного и физического слоёв — принципиально.

**Пример.** Агент-аналитик высокого уровня получает задачу составить договор аренды. Рабочая память: текущий разговор, техническое задание, черновик договора. Эпизодическая память при сжатии контекста сохраняет промежуточные версии. При следующей похожей задаче агент извлекает: «в прошлый раз заказчик трижды правил раздел ответственности — при первом же предъявлении проверять именно его». Семантическая память даёт: «договоры аренды в юрисдикции X требуют обязательного пункта Y». Процедурная память, накопленная за месяцы работы, содержит правило: «при анализе любого договора первым проверяй юрисдикцию, вторым — сроки, третьим — штрафные санкции» — правило, которое агент выработал сам, а не получил от архитектора. Все три потока поступают в рабочую память и формируют итоговый договор.

**Связь с другими паттернами:** Рабочая память использует PATTERN-027 (Семантическое сжатие контекста). Эпизодическая использует PATTERN-027 и PATTERN-029 (Журнал сессии). Семантическая использует PATTERN-032 (Agentic RAG), PATTERN-033 (Семантический веер), PATTERN-037 (Мультивекторный индекс). Процедурная использует PATTERN-020 (Храповой цикл) как механизм конденсации правил и PATTERN-025 (Трёхуровневая архитектура правил) как механизм их хранения и применения. PATTERN-038 (Градиентное хранение) — независимый инженерный паттерн физического хранения, обслуживающий когнитивные уровни. PATTERN-044 (HITL) — один из катализаторов формирования процедурной памяти.

**Экспериментальная проверка:** Требуется. План: (1) сравнить качество решений агента с unified-моделью против агента с одной лишь рабочей памятью на задачах, требующих обращения к прошлому опыту; (2) отдельно проверить эффект процедурной памяти на высокоинтеллектуальных агентах в HITL-контуре — измерить, ускоряет ли наличие процедурного уровня движение по кривой доверия (PHILOSOPHY-007).
