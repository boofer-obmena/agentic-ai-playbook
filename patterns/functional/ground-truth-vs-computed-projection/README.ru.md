# Паттерн 8. «Фундаментальный источник против вычисляемой проекции» (Ground Truth vs. Computed Projection)

[Read in English](README.md)

**Проблема:** Когда агент синтезирует итоговый артефакт (ТЗ, отчёт, аналитическую записку), он склонен «причёсывать» входные данные: сглаживать противоречия, выбирать один из конкурирующих фактов, строить гладкий нарратив. Это разрушает сигналы о реальных несоответствиях. Каскад искажений накапливается.

**Решение:** Система данных жёстко разделяется на два независимых слоя. Слой сырых фактов (Ground Truth Layer): неизменяемые, версионированные записи в базе данных. Факты никогда не перезаписываются — только добавляются новые версии. Каждый факт содержит метаданные: источник, дата записи, коэффициент точности сигнала. Слой вычисляемых проекций (Computed Projection Layer): ТЗ, код, аналитические отчёты и любые синтезированные артефакты. Проекции создаются под конкретный запрос и являются временными. Исправление данных всегда вносится в слой фактов, после чего система автоматически пересобирает все зависимые проекции.

**Пример:** Функциональный архитектор обнаруживает ошибку в ТЗ: неверно указан тип данных поля. В целевой архитектуре: архитектор исправляет запись в Регистре ФТ (слой фактов). Система автоматически пересобирает ТЗ, генерирует обновлённые тест-кейсы и уведомляет разработчика об изменении.

**Экспериментальная проверка:** Внести два взаимно противоречащих требования в слой фактов. В целевом режиме агент обязан явно выделить блок «Критическое противоречие» с указанием обоих конкурирующих фактов и запросить разрешение у человека.

**История применения:** Не применялся. Раздел заполняется по результатам реального использования паттерна: контекст задачи, что сработало, что потребовало корректировки, итоговые выводы.
