# Ground Truth Vs Computed Projection

> **Паттерн 8. «Фундаментальный источник против вычисляемой проекции» (Ground Truth vs. Computed Projection)**

> *[English translation pending — original Russian text preserved in sections below.]*

[Читать на русском](README.ru.md)

## Problem

Когда агент синтезирует итоговый артефакт (ТЗ, отчёт, аналитическую записку), он склонен «причёсывать» входные данные: сглаживать противоречия, выбирать один из конкурирующих фактов, строить гладкий нарратив. Это разрушает сигналы о реальных несоответствиях. Каскад искажений накапливается.

## Solution

Система данных жёстко разделяется на два независимых слоя. Слой сырых фактов (Ground Truth Layer): неизменяемые, версионированные записи в базе данных. Факты никогда не перезаписываются — только добавляются новые версии. Каждый факт содержит метаданные: источник, дата записи, коэффициент точности сигнала. Слой вычисляемых проекций (Computed Projection Layer): ТЗ, код, аналитические отчёты и любые синтезированные артефакты. Проекции создаются под конкретный запрос и являются временными. Исправление данных всегда вносится в слой фактов, после чего система автоматически пересобирает все зависимые проекции.

## Example

Функциональный архитектор обнаруживает ошибку в ТЗ: неверно указан тип данных поля. В целевой архитектуре: архитектор исправляет запись в Регистре ФТ (слой фактов). Система автоматически пересобирает ТЗ, генерирует обновлённые тест-кейсы и уведомляет разработчика об изменении.

## Experimental Verification

Внести два взаимно противоречащих требования в слой фактов. В целевом режиме агент обязан явно выделить блок «Критическое противоречие» с указанием обоих конкурирующих фактов и запросить разрешение у человека.
