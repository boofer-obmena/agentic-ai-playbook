# Orchestrator Driven Explicit State Flow

> **Паттерн 11. «Оркестратор-дирижёр с явным потоком состояния» (Orchestrator-Driven Explicit State Flow)**

**Проблема: В архитектуре событийной хореографии агенты общаются между собой напрямую. При отладке такой системы крайне сложно понять, почему конкретный агент получил именно эти данные именно в этот момент. В критически важных системах такая непредсказуемость неприемлема.:**



**Решение: Все взаимодействия между агентами управляются единым централизованным компонентом — Оркестратором, реализующим конечный автомат состояний. Агенты не общаются между собой напрямую. Каждый агент получает задание исключительно от Оркестратора и возвращает результат исключительно ему. Оркестратор явно передаёт каждому агенту строго необходимый ему набор данных — зафиксированную версию, а не ссылку на изменяемое состояние. Каждый шаг записывается в журнал, пригодный для аудита и воспроизведения.:**



**Пример: Запрос: рассчитать кредитный лимит для контрагента. Шаг 1: Оркестратор вызывает агента-аналитика с набором финансовых показателей (версия v1.0). Шаг 2: Оркестратор вызывает агента-оценщика, передавая ему результат аналитика (v1.0) и исходные данные (v1.0). Агент-оценщик работает только с тем, что явно передал ему Оркестратор — это гарантирует полную воспроизводимость.:**



**Экспериментальная проверка: Смоделировать один и тот же многошаговый процесс в двух режимах: событийная хореография и оркестрация. Ввести искусственную сетевую задержку на одном из шагов. В режиме оркестрации Оркестратор гарантирует, что второй агент всегда получает именно те данные, которые породил первый.:**



**История применения: Не применялся. Раздел заполняется по результатам реального использования паттерна: контекст задачи, что сработало, что потребовало корректировки, итоговые выводы.:**

#### **Расширение. Парадигма «цель-результат» (Goal-Result Paradigm)**

В классическом взаимодействии человек получал текст от модели и сам выполнял следующий шаг: открывал почту, вставлял текст, нажимал отправку. Агент с машиной состояний устраняет человека как «живого маршрутизатора». Ключевые требования: (1) Агент помнит глобальную цель через все промежуточные шаги. (2) Каждый шаг фиксирует статус выполнения. (3) При ошибке внешней системы — агент не сдаётся, а повторяет попытку с экспоненциальной задержкой. (4) Промежуточные этапы скрыты от пользователя — он видит только финальный результат.
