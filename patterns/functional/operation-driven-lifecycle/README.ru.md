# Паттерн 3. «Жизненный цикл, управляемый операциями» (Operation-Driven Lifecycle)

**Проблема:** Когда агенты могут произвольно менять статусы задач и артефактов, возникает хаос: задача может оказаться одновременно «в разработке» и «на тестировании», или перейти в статус «Готово» без прохождения обязательных этапов. Это делает конвейер непредсказуемым и воспроизводимость процесса невозможной.

**Решение:** Статус задачи или артефакта изменяется исключительно как результат выполнения формализованной операции-транзакции. Ни один агент не может «просто поменять статус» напрямую. Единственным автоматом переходов между состояниями является Оркестратор. Агенты инициируют операции, но именно Оркестратор выполняет переход, предварительно проверив все предусловия операции.

**Пример:** Разработчик завершил реализацию. Он не может самостоятельно перевести задачу в статус «Готово к тестированию». Он вызывает операцию «Передать на тестирование». Оркестратор проверяет предусловия: наличие ссылки на коммит, успешный локальный запуск тестов, заполненные поля документации. Только при выполнении всех предусловий Оркестратор переводит задачу в нужный статус.

**Экспериментальная проверка:** Смоделировать серию нелогичных команд агентов: попытку перевести задачу в «Готово» без коммита, попытку начать тестирование без ФТ, попытку закрыть задачу с открытыми дефектами. Убедиться, что Оркестратор блокирует все попытки с информативным диагностическим сообщением.

**История применения:** Не применялся. Раздел заполняется по результатам реального использования паттерна: контекст задачи, что сработало, что потребовало корректировки, итоговые выводы.
