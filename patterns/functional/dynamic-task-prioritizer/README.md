# Dynamic Task Prioritizer

> **Паттерн 48. «Динамический приоритизатор очереди задач» (Dynamic Task Prioritizer)**

> *[English translation pending — original Russian text preserved in sections below.]*

[Читать на русском](README.ru.md)

## Problem

В мультиагентной системе с несколькими параллельно выполняющимися задачами порядок обработки, заданный при старте, неизбежно расходится с реальностью. Агенты застревают на задачах, освобождаются раньше плана, возникают новые срочные запросы. Без механизма динамической переприоритизации система либо простаивает (ждёт отстающего агента), либо пропускает критические задачи (обрабатывает по FIFO). При этом возлагать приоритизацию на Оркестратора — значит заставлять его переключаться между ролями дирижёра и планировщика, теряя контекст и замедляя выполнение.

## Solution

В архитектуру вводится отдельный компонент — Приоритизатор, отвечающий на вопрос «что и когда делается». Оркестратор отвечает на вопрос «кто что делает»; Приоритизатор отвечает на вопрос «в каком порядке». Это разделение предотвращает смешение когнитивных функций в одном компоненте.

Приоритизатор получает от Оркестратора полный план выполнения и список активных задач с их статусами. На основе декларативных критериев (срочность, важность, зависимости, доступность исполнителей) он выстраивает очередь. Ключевое свойство: приоритизация — не разовое действие при старте, а непрерывный процесс. Приоритизатор отслеживает фактические времена выполнения: если агент застрял на задаче — следующие задачи, не зависящие от застрявшей, продвигаются в очереди. Если агент освободился раньше — Приоритизатор назначает ему следующую задачу из очереди, оптимизируя общее время выполнения плана.

Приоритизатор не меняет план — он меняет очерёдность в рамках плана. Зависимости, заложенные в плане Оркестратором, остаются нерушимыми.

Шкала приоритетов — архитектурный параметр, настраиваемый под проблемный домен. Минимальная: три уровня (критичное / важное / рядовое). Расширенная: weighted scoring по urgency × importance × effort × risk. Приоритизатор оперирует шкалой, заложенной архитектором.

## Example

В системе одновременно идут три задачи: (А) подготовка срочного договора для ключевого клиента — критично, (Б) еженедельный отчёт для руководства — важно, (В) обновление внутренней базы знаний — рядовое. При старте очередь: А → Б → В. Задача А застряла — агент-юрист ждёт ответа от внешнего контрагента. Приоритизатор обнаруживает: Б не зависит от А. Продвигает Б в начало очереди, не трогая план. Когда контрагент отвечает, А возвращается в работу. Задача В остаётся последней. Общее время выполнения сокращено за счёт того, что система не простаивала в ожидании А.

## Связь с другими паттернами

Дополняет PATTERN-011 (Оркестратор): Оркестратор владеет планом и распределяет работу, Приоритизатор управляет очерёдностью. Дополняет PATTERN-006 (Умный диспетчер): Диспетчер выбирает исполнителя под задачу, Приоритизатор выбирает задачу под момент. Связан с PATTERN-046 (Параллелизация): чем больше параллельных задач, тем важнее динамическая приоритизация. Связан с PATTERN-047 (Мониторинг с дрейф-детекцией): дрейф в одной задаче может вызвать каскадную переприоритизацию очереди.

## Experimental Verification

Требуется. План: сравнить общее время выполнения пула из 5+ задач с динамической приоритизацией против FIFO. Измерить: среднее время завершения задачи, время простоя агентов, долю критических задач, обработанных с задержкой.
