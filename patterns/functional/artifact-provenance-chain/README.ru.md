# Паттерн 1. «Цепочка происхождения артефакта» (Artifact Provenance Chain)

**Проблема:** При многошаговых трансформациях артефакта теряется обоснование: неясно, из чего и почему получился текущий результат. Когда ТЗ создаётся на основе ФТ, ФТ — на основе User Story, а User Story — из интервью, цепочка происхождения легко обрывается. Любой участник процесса должен быть способен проследить путь от финального артефакта до первоначального источника.

**Решение:** Для каждого артефакта хранятся два обязательных атрибута. «Источник» — неизменный идентификатор эталонного содержания, из которого был порождён артефакт. «Основание» — идентификатор операции или документа, на основании которого было произведено изменение. При передаче артефакта следующему агенту Источник копируется без изменений, Основание обновляется. Дополнительно: для каждого чанка в памяти и каждого сгенерированного артефакта хранится идентификатор версии модели, осуществившей генерацию. Все вычисляемые проекции содержат ссылку на конкретную запись в слое сырых фактов.

**Пример:** QA-агент получает задачу протестировать функцию. Он открывает тест-кейс и видит ссылку на ТЗ (Основание). Из ТЗ переходит к ФТ (Источник ТЗ). Из ФТ — к исходной User Story. Таким образом, при обнаружении бага QA-агент способен определить, на каком из этапов возникло исходное требование, и передать точный диагноз обратно в конвейер.

**Экспериментальная проверка:** Взять сложный артефакт и намеренно «раздробить» его на несколько дочерних. Проверить, что каждый дочерний артефакт сохраняет корректную ссылку на оригинал. Провести обратный обход: от листового артефакта до корневого источника. Успех: полная прослеживаемость без обрывов цепочки.

**История применения:** Не применялся. Раздел заполняется по результатам реального использования паттерна: контекст задачи, что сработало, что потребовало корректировки, итоговые выводы.
