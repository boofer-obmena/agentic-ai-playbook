# Ratchet Loop

> **Паттерн 20. «Ratchet Loop / Храповой цикл самоулучшения» (Ratchet Loop)**

> *[English translation pending — original Russian text preserved in sections below.]*

[Читать на русском](README.ru.md)

## Problem

Агентные системы деградируют без механизма самоулучшения. Накопленный опыт эксплуатации — ошибки, наблюдения, пограничные случаи — не конвертируется в улучшение правил поведения агента. Система остаётся статичной, несмотря на растущий объём информации о собственных слабых местах.

## Solution

Вводится замкнутый цикл: Наблюдение → Гипотеза → Тест → Фиксация улучшения. Агент-ревьюер по расписанию анализирует историю взаимодействий агента за период, формулирует гипотезы об улучшении правил и записывает их в промежуточный буфер (например, server_notes.md). После верификации подтверждённые гипотезы переносятся в основной свод правил (server_rules.md). Принцип «храповика»: система только движется вперёд — подтверждённые улучшения не откатываются, неподтверждённые гипотезы не попадают в правила автоматически.

## Example

Агент-администратор сервера трижды за неделю пытался выполнить команду без sudo и получал ошибку. Агент-ревьюер обнаруживает паттерн и формулирует гипотезу: «Добавить правило: перед командами, требующими повышенных привилегий, проверять наличие sudo». Гипотеза помещается в буфер. Архитектор верифицирует и переносит правило в основной свод. Следующая итерация агента уже работает с обновлёнными правилами.

## Experimental Verification

Намеренно создать в поведении агента систематическую ошибку (например, неверный порядок вызова инструментов). Запустить агента-ревьюера. Проверить: ревьюер обнаруживает паттерн ошибки, формулирует конкретную гипотезу улучшения, записывает в буфер. После ручного подтверждения правило добавлено в основной свод. Следующий прогон агента ошибку не воспроизводит.

Прогрессия автономности

Уровень 1 — Агент выполняет явно заданные задачи, не изменяет собственное поведение.

Уровень 2 — Агент фиксирует наблюдения и предлагает улучшения на рассмотрение человека.

Уровень 3 — Агент самостоятельно вносит улучшения в рамках заранее одобренных границ, фиксирует изменения в журнале.

Уровень 4 (предельный) — Агент создаёт задачи для других агентов, которые их выполняют, тестируют и докладывают результаты третьим агентам. Человек выполняет только функцию финального одобрения (кнопка «approve»). Эталонный показатель уровня 4: ~90% задач выполняются автономно. Большинство производственных систем сегодня работают на уровнях 2–3. Уровень 4 — горизонт проектирования на 2–3 года.

## Application History

Частично реализован при создании агента-администратора сервера Mac Mini (апрель 2026). Агент-ревьюер запускается по расписанию в 05:00, читает agent_chat_memory за прошедшие сутки, формулирует наблюдения в server_notes.md. Соответствует уровням 2–3 прогрессии автономности. Что потребовало корректировки: граница между «наблюдением» и «правилом» оказалась нечёткой — нужно формализовать критерии перехода гипотезы из буфера в правила.
