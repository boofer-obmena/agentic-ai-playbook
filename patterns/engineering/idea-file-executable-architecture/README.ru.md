**Проблема:** Архитектурная документация традиционно пассивна: она описывает систему в виде текста, схем и диаграмм. Перенос этого описания в рабочий код, конфигурации и промпты требует ручной интерпретации каждый раз, когда нужно развернуть или обновить компонент. Это замедляет итерации и порождает рассогласование между документацией и реальной системой.

**Решение:** Вводится формат Исполнимого архитектурного артефакта (Idea File) — структурированный декларативный файл на человекочитаемом языке (Markdown с расширениями), описывающий роль агента, его инструменты, правила взаимодействия и критерии автономности. Функциональный архитектор агентного конвейера загружает Idea File в Оркестратор. Оркестратор интерпретирует файл и автоматически: генерирует системный промпт агента, настраивает его инструментальный манифест, регистрирует агента в оркестре, настраивает мониторинг. Idea File является одновременно и документацией, и конфигурацией. При изменении файла система автоматически обновляет соответствующий агент.

**Пример:** Архитектор создаёт файл agent-notifier.idea.md. Содержание: роль — «Уведомить указанных участников о смене статуса задачи», триггер — «Изменение статуса любой задачи в конвейере», инструменты — «send_notification(recipient, message)», правила — «Уведомить всех участников задачи. Текст сообщения формировать из шаблона.» Архитектор передаёт файл Оркестратору. Через 20 минут агент-нотификатор активен и начинает отправлять уведомления.

**Экспериментальная проверка:** Написать Idea File для простейшего агента — нотификатора о смене статуса задачи. Передать в Оркестратор. Измерить время от передачи файла до момента, когда агент отправил первое корректное уведомление. Цель: менее 1 часа без ручного кодирования. Изменить один параметр в Idea File и проверить, что система автоматически обновила конфигурацию агента.
