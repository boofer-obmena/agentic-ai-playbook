**Проблема:** Обновление модели, используемой для генерации векторных эмбеддингов, требует полной переиндексации всей базы знаний. При значительном объёме данных этот процесс занимает дни и требует остановки конвейера: нельзя одновременно обслуживать запросы со старыми эмбеддингами и генерировать новые.

**Решение:** Используется механизм мультивекторной индексации. При обновлении модели новая модель регистрируется в векторной базе параллельно со старой. Индексы сосуществуют. Поисковый запрос выполняется одновременно против обоих индексов, результаты ранжируются и объединяются. В фоновом режиме запускается процесс пересчёта эмбеддингов для всех документов новой моделью. По мере готовности фрагментов поиск по ним переключается на новый индекс. После завершения полного пересчёта старый индекс удаляется. Конвейер не прерывается ни на каком этапе.

**Пример:** В базе знаний 50 000 документов. Пересчёт эмбеддингов новой моделью занимает 8 часов. В течение этих 8 часов конвейер продолжает обслуживать запросы. Для каждого запроса: документы, уже переиндексированные новой моделью, ищутся через новый индекс; ещё не переиндексированные — через старый. Качество поиска не деградирует, время ответа остаётся в рамках SLA.

**Экспериментальная проверка:** Запустить активный поток поисковых запросов с фиксацией задержки и релевантности. В это же время запустить фоновую переиндексацию 50% базы. Проверить в процессе переиндексации: задержка ответов не выросла сверх SLA, релевантность результатов не снизилась.

**История применения:** Не применялся. Раздел заполняется по результатам реального использования паттерна: контекст задачи, что сработало, что потребовало корректировки, итоговые выводы.
