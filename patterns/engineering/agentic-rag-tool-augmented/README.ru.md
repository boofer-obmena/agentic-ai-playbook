**Проблема:** Стандартный RAG (однократный поиск → ответ) недостаточен для аналитических задач, требующих итеративного исследования: сначала найти общую картину, затем уточнить детали, затем произвести расчёт. Агент, ограниченный одним поисковым запросом, либо даёт поверхностный ответ, либо галлюцинирует недостающие детали.

**Решение:** Агент получает расширенный Инструментальный манифест, включающий не только инструменты поиска, но и аналитические инструменты: search_in_knowledge_base (поиск по базе знаний), calculator (арифметические вычисления), date_calculator (операции с датами и периодами), cross_reference (проверка соответствия между двумя источниками). Агент самостоятельно решает, сколько итераций «поиск → анализ → повторный поиск» ему необходимо для формирования обоснованного ответа. Каждый вызов инструмента фиксируется в цепочке рассуждений (Chain-of-Thought) и доступен для аудита.

**Пример:** Задача: «Суммировать плановые трудозатраты по всем открытым задачам разработчика Иванова за Q1 2025 и сравнить с фактическими часами из системы учёта.» Агент: (1) вызывает search_in_knowledge_base с запросом о задачах Иванова в Q1 2025, получает список из 7 задач; (2) для каждой задачи вызывает search_in_knowledge_base для получения планового бюджета часов; (3) вызывает calculator для суммирования плановых часов; (4) вызывает search_in_knowledge_base для получения фактических часов из системы учёта; (5) вызывает calculator для расчёта отклонения; (6) формирует ответ с указанием каждого шага и источника данных.

**Экспериментальная проверка:** Сформулировать задачу, которая заведомо требует минимум 3 итераций поиска и хотя бы 1 вычисления. Проверить: агент совершает необходимое количество вызовов инструментов, каждый вызов задокументирован в Chain-of-Thought, финальный ответ точен и содержит ссылки на источники каждого числа.

**История применения:** Не применялся. Раздел заполняется по результатам реального использования паттерна: контекст задачи, что сработало, что потребовало корректировки, итоговые выводы.
